# Кляузная (plaint)

Сатирический веб-сервис для «анонимных жалоб»: пользователь заполняет форму, проходит театральную валидацию, а сообщение сохраняется локально — **никуда не уходит по почте и в сторонние сервисы**. Текст задуман как катарсис, а не как официальное обращение.

Стек: **Nuxt 4**, **Vue 3**, сервер **Nitro** (режим `node-server`), хранилище — **SQLite** через встроенный модуль Node [`node:sqlite`](https://nodejs.org/api/sqlite.html).

## Требования

- **Node.js ≥ 22.5** — нужен нативный `node:sqlite` (на более старых версиях сервер не поднимется).
- **npm** (или совместимый менеджер пакетов).

Проверка:

```bash
node -e "import('node:sqlite').then(() => console.log('OK'))"
```

## Быстрый старт

```bash
git clone <url-репозитория> plaint
cd plaint
npm install
cp .env.example .env
# отредактируйте .env — минимум пароль админки и при необходимости публичный URL
npm run dev
```

Приложение: **http://localhost:3000**

Первый запуск создаёт каталог `data/` и файл БД `data/plaint.sqlite` автоматически.

## Переменные окружения

Скопируйте [`.env.example`](.env.example) в `.env`. Файл `.env` в git не попадает.

| Переменная | Обязательно | Описание |
|------------|-------------|----------|
| `NUXT_ADMIN_LOGIN` | для админки | Логин входа в `/admin` |
| `NUXT_ADMIN_PASSWORD` | для админки | Пароль (используется и для подписи сессионной cookie) |
| `NUXT_PUBLIC_SITE_URL` | для SEO | Публичный URL **без** завершающего `/`, например `https://plaint.example.com`. Нужен для canonical, Open Graph, `sitemap.xml` и `robots.txt` |

Если **не заданы** логин и пароль админа:

- вход в админку недоступен (**503**);
- список и удаление жалоб через API тоже **503** (данные не отдаются «в открытую»).

В Nuxt 4 переменные с префиксом `NUXT_` попадают в `runtimeConfig` ([документация](https://nuxt.com/docs/getting-started/configuration#environment-variables)).

## npm-скрипты

| Команда | Назначение |
|---------|------------|
| `npm run dev` | Режим разработки с hot reload |
| `npm run build` | Production-сборка в `.output/` |
| `npm run preview` | Локальный просмотр собранного приложения |
| `npm run generate` | Статическая генерация (для этого проекта основной сценарий — SSR + API, не `generate`) |

После сборки:

```bash
npm run build
node .output/server/index.mjs
```

Порт по умолчанию задаётся через `PORT` / `NITRO_PORT` (см. [Nitro](https://nitro.unjs.io/deploy/node)).

## Страницы сайта

| Путь | Доступ | Описание |
|------|--------|----------|
| `/` | публичный | Главная, ссылка на форму |
| `/form` | публичный | Форма жалобы (клиентская валидация + отправка в API) |
| `/sent` | публичный | Экран «отправлено» (`noindex`) |
| `/admin` | UI публичный, данные — по API | Просмотр и удаление жалоб после входа (`noindex`) |

Дополнительно:

- `GET /robots.txt` — закрывает `/admin` и `/api/` для роботов;
- `GET /sitemap.xml` — только если задан `NUXT_PUBLIC_SITE_URL` (страницы `/` и `/form`).

## HTTP API

Все маршруты под `/api/` — JSON, ошибки в формате Nitro/h3 (`statusCode`, `statusMessage`).

### Публичные

#### `POST /api/complaints`

Создать жалобу.

**Тело (JSON):**

| Поле | Тип | Обязательно | Ограничения |
|------|-----|-------------|-------------|
| `body` | `string` | да | не пустой после `trim`, макс. **600** символов |
| `name` | `string` | нет | опциональное имя/псевдоним, макс. **28** символов; пустая строка игнорируется |

Минимальная длина текста (≥ 6 символов) и «театральная» валидация на `/form` — **только на клиенте**. API проверяет пустой `body` и верхние пределы. Константы лимитов: [`shared/complaintLimits.ts`](shared/complaintLimits.ts).

**Успех (200):** объект жалобы:

```json
{
  "id": 1,
  "name": "Товарищ Иван",
  "body": "Текст жалобы",
  "created_at": "2025-07-15T12:00:00.000Z"
}
```

`name` может быть `null`.

**Ошибки:**

| Код | Когда |
|-----|--------|
| 400 | Нет текста или превышена длина |
| 429 | Превышен лимит отправок с IP (см. ниже) |

### Только для администратора

Требуется cookie `plaint_admin_session` (выдаётся после успешного логина). Без настроенных `NUXT_ADMIN_*` — **503**.

#### `POST /api/admin/login`

```json
{ "login": "…", "password": "…" }
```

Ответ: `{ "ok": true }` и httpOnly-cookie.

#### `POST /api/admin/logout`

Сбрасывает сессию: `{ "ok": true }`.

#### `GET /api/complaints`

Массив жалоб, сортировка по `id` по убыванию.

#### `DELETE /api/complaints/:id`

Удалить по числовому `id`. Успех: `{ "ok": true }`, иначе **404**.

## База данных

- Файл: **`data/plaint.sqlite`** (в git не коммитится).
- Режим журнала: **WAL** (`*.sqlite-wal`, `*.sqlite-shm` — тоже в `.gitignore`).

Таблица `complaints`:

| Колонка | Тип | Описание |
|---------|-----|----------|
| `id` | INTEGER PK | Автоинкремент |
| `name` | TEXT | Имя/псевдоним или NULL |
| `body` | TEXT NOT NULL | Текст жалобы |
| `created_at` | TEXT | ISO-подобная метка времени (UTC) |

При старте Nitro-плагин [`server/plugins/db.ts`](server/plugins/db.ts) открывает БД и при необходимости выполняет лёгкие миграции схемы ([`server/utils/db.ts`](server/utils/db.ts)).

**Резервное копирование:** достаточно периодически копировать `data/plaint.sqlite` (при WAL лучше в момент простоя или через `.backup` SQLite).

## Админка

1. Задайте `NUXT_ADMIN_LOGIN` и `NUXT_ADMIN_PASSWORD` в `.env`.
2. Откройте **/admin**, войдите.
3. Список обновляется кнопкой «Обновить»; удаление — с подтверждением в браузере.

Сессия: **7 дней**, cookie `httpOnly`, `sameSite=lax`, в production — флаг `secure`. Смена пароля в `.env` инвалидирует старые сессии (токен завязан на пароль).

## Ограничения и безопасность

| Что | Лимит |
|-----|--------|
| Отправка жалоб (`POST /api/complaints`) | **5 запросов** с одного IP за **15 минут** (учитываются и неуспешные попытки) |
| Неудачный вход в админку | **5 ошибок** за **15 минут** → блок IP на **15 минут** + нарастающая задержка ответа |
| Сравнение логина/пароля | `timingSafeEqual` |

Лимиты хранятся **в памяти процесса**: после рестарта счётчики сбрасываются; при нескольких инстансах без общего хранилища лимиты не синхронизируются (для одного VPS это обычно приемлемо).

Форма на `/form` задаёт `maxlength` на полях и дублирует лимиты **28 / 600** в логике подсказок; минимальная длина текста проверяется только там, не в API.

## Продакшен

1. Установите Node **≥ 22.5** на сервере.
2. Задайте все переменные из `.env.example` (на хостинге — через панель или systemd/PM2).
3. `npm ci && npm run build`
4. Запускайте **`node .output/server/index.mjs`** под process manager (PM2, systemd и т.д.).
5. Обеспечьте **запись в каталог `data/`** рядом с рабочей директорией приложения (или смонтируйте том).
6. Проксируйте HTTPS снаружи (nginx, Caddy) — для secure-cookie админки нужен HTTPS в production.

### CI/CD (Ubuntu + GitHub)

- **CI** (`.github/workflows/ci.yml`): на каждый push/PR в `main` — `npm ci`, typecheck, build.
- **Deploy** (`.github/workflows/deploy.yml`): после успешной проверки на push в `main` — SSH на сервер, `git reset --hard origin/main`, `deploy/deploy.sh`.
- Пошаговая настройка сервера, nginx, systemd, секреты Actions: **[docs/DEPLOY-UBUNTU.md](docs/DEPLOY-UBUNTU.md)**.

Каталоги сборки (`.output`, `.nuxt`) в репозиторий не кладутся — они появляются после `build`.

├── app/                    # Nuxt app (Vue)
│   ├── pages/              # Маршруты: index, form, sent, admin
│   ├── components/         # UI: форма, кнопки, оболочка

│   └── assets/css/         # Стили и шрифты

│   ├── routes/             # robots.txt, sitemap.xml
